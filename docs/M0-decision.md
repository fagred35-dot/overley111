## 3. Вопрос 3: скрытие системного курсора

- Работает ли `overlay-only` на практике (клик сквозь окно)? **да** — `WS_EX_TRANSPARENT | WS_EX_LAYERED | WS_EX_TOOLWINDOW`, клики проходят насквозь, прицел остаётся поверх активного окна (проверено на стенде).
- `SetSystemCursor(blank)`: как восстанавливается после `taskkill /F`? (20 прогонов: ___/20) — восстановление по флагу `--restore-cursor` работает; штатный выход восстанавливает курсор сам. Серия 20/20 после `taskkill /F` **ожидает**.
  **Найдено и исправлено на стенде (2026-10-11):** первая версия подмены давала «чёрный квадрат» вместо невидимого курсора — нулевая AND-маска у `CreateCursor` означает непрозрачный чёрный пиксель; исправлено на AND=0xFF/XOR=0. Заодно: `SetSystemCursor` забирает владение HCURSOR, поэтому каждому системному id теперь создаётся свой курсор (раньше один handle передавался 11 раз = use-after-free).
- Есть ли предупреждения античита/AV на `SPI_SETCURSORS`? **ожидает** (стенд без античита; см. PLAN §3.3 — красные линии не нарушаются: только `SetSystemCursor`, без хуков/инъекций).

## 5. Вопрос 5: хоткеи

| Окружение | `RegisterHotKey` долетает? | Какие комбинации не работают | Нужен ли LL-хук |
| --- | --- | --- | --- |
| Desktop Windows 11 (стенд тестера) | да: F7, F8, F9 | **F12 занята** сторонней программой | нет |
| В игре (ожидает M0-6) | | | |

**Решение (промежуточное):** глобальные хоткеи работают на десктопе без LL-хука. Так как F12 на
стенде оказался занят, в спайке добавлена цепочка запасного выхода **F12 → F10 → Pause/Break →
Ctrl+Alt+Q** (берётся первая свободная, фактическая комбинация печатается при старте). В продукте
(M5) — пользовательская переназначаемая схема + автоматический поиск свободной комбинации. Проверка
«долетают ли хоткеи в игре» остаётся открытой (M0-6).
