## 1. TL;DR

**Продукт.** Лёгкий оверлей для Windows, который рисует пользовательский прицел поверх игры. Без инжекта DLL, без чтения памяти игры, без симуляции ввода — это отдельное прозрачное click-through окно, которое DWM композитит поверх игры. Именно такая архитектура считается безопасной с точки зрения античитов (так работают CrossOver, HudSight, Crosshair X).

**Пять фич из запроса и как они решаются:**

| # | Фича | Решение | Этап |
| --- | --- | --- | --- |
| 1 | Заменить мышку прицелом из приложения | Два режима: `center` (прицел в центре экрана, для FPS) и `cursor` (прицел следует за курсором). Плюс 3 стратегии «спрятать системный курсор» с гарантированным восстановлением после краша | M1–M2 |
| 2 | Авто-запуск с какой-то программой, главное — без инжекта | Наблюдатель процессов: опрос снапшота имён процессов 1–2 Гц + `GetForegroundWindow`. Никаких хендлов на процесс игры, никаких хуков в неё. По совпадению — поднимает оверлей и применяет нужный пресет | M3 |
| 3 | Пресеты «какой прицел с каким приложением» + пользователь может менять | Профиль = правило (exe/путь/подстрока) → пресет + поведение. Редактор пресетов, дублирование, импорт/экспорт `.ovcross`, ручное переключение хоткеем | M3–M4 |
| 4 | В галерее — инструкция для ИИ (скопировал → сходил на любой ИИ-сайт → вставил код в приложение) | Карточка «Создать прицел с ИИ» прямо в сетке галереи: кнопки копирования промпта (RU/EN), ссылка на диалог импорта, валидация ответа ИИ, живой предпросмотр, понятная ошибка + готовый follow-up промпт «исправь» | M4–M5 |
| 5 | Современный UI + максимальная кастомизация | Tauri 2 + React/TS/Tailwind: тёмная «стеклянная» тема, живое превью на игровом фоне, слои, анимации, реактивность на мышь, ~80 параметров, RU/EN | M4–M7 |

**Главное техническое ограничение (принять сразу).** Оверлей виден в оконном и borderless-режиме. В настоящем эксклюзивном fullscreen (FSE) DWM отключается и сторонние окна поверх игры не рисуются. На Windows 11 большинство DX12-игр и так работают через flip-model/borderless, поэтому проблема затрагивает меньшинство тайтлов. Наша позиция: (а) честно пишем об этом в FAQ и показываем подсказку при детекте FSE, (б) рекомендуем borderless, (в) планом Б держим виджет Xbox Game Bar — «доверенная» платформа оверлеев от Microsoft ([детали](COMPATIBILITY.md)).

**Оценка.** ~124 рабочих дня: играбельный MVP — 44 р.д., бета — +54 р.д., релиз 1.0 — +26 р.д. Один разработчик ≈ 6 месяцев, двое ≈ 3,5 месяца.

## 2. Проблема и позиционирование

### 2.1 Зачем это нужно

- Во многих играх встроенный прицел убогий: нет нужной формы, нельзя сделать тонкую обводку, нельзя точку с кольцом, нельзя цвет под карту/освещение.
- В части игр прицела нет вовсе (старые тайтлы, эмуляторы, браузерные шутеры, «day-one» порты).
- Игроки хотят один и тот же прицел во всех играх — мышечная память.
- Существующие решения: либо тяжёлые (Electron, 200+ МБ ОЗУ), либо платные/закрытые, либо с убогим UI, либо без возможности сделать «свой» прицел (только галерея готовых).

### 2.2 Чем мы отличаемся

1. **Лёгкость как требование, а не как лозунг.** В игровом режиме живёт только нативное окно-оверлей (цель ≤ 25 МБ ОЗУ, 0% CPU на статичном прицеле). UI настроек выгружается.
2. **ИИ-конвейер в галерее.** Пользователь не учится рисовать: копирует промпт, просит любой ИИ («сделай прицел как у s1mple, но неоновый»), вставляет JSON — получает рабочий прицел с превью. Это уникальная механика: конкуренты дают либо галерею, либо редактор, но не «сгенерируй сам».
3. **Максимальная кастомизация.** Слои, градиенты, обводка, свечение, анимации, реактивность на скорость мыши/кнопки, свои PNG/SVG.
4. **Профили по играм.** Один запуск — и для Valorant один прицел, для CS2 другой, для Apex третий, автоматически.
5. **Прозрачность и комплаенс.** Публичная страница «что мы НЕ делаем», подписанный бинарник, открытый формат пресетов.

### 2.3 Конкуренты (референсы)

| Продукт | Что берём себе | Чего не повторяем |
| --- | --- | --- |
| CrossOver (open source, 530+ прицелов, Win/macOS/Linux) | Open-source модель, большая галерея, «не банится» как ключевое сообщение | Electron-тяжесть, слабый редактор |
| HudSight (Steam) | Мастерская/галерея пользовательских прицелов, режим Game Bar для FSE | Платность, устаревший UI |
| Crosshair X (Steam/MS Store) | Пер-гейм профили, авто-детект, «нулевой input lag» как маркетинг | Закрытость, спорные заявления про «kernel overlay» |
| Valorant Crosshair Companion | Формулировки «безопасно для Vanguard» и FAQ — буквально образец текста для нашей страницы комплаенса | Узкая заточенность под одну игру |

## 3. Скоуп

### 3.1 В скоупе (v1.0)

Windows 10 21H2+ / Windows 11, x64. Оверлей прицела, редактор, галерея, ИИ-импорт, профили по приложениям, хоткеи, трей, автозапуск, i18n RU/EN, установщик + portable, автообновление.

### 3.2 Вне скоупа v1.0 (бэклог фазы 2)

macOS/Linux, мобильный компаньон, облачная галерея/синхронизация, сервер сообщества, виджет Xbox Game Bar, Steam Workshop, скины/темы оформления окна настроек от пользователей, «динамический прицел по отдаче игры», записи/клипы, стримерские интеграции (OBS-плагин), ARM64.

### 3.3 Категорически НЕ делаем (красные линии)

Это одновременно требование античит-комплаенса и юридическая защита продукта:

- ❌ Инжект DLL / подмена модулей в процесс игры.
- ❌ Чтение или запись памяти игрового процесса, `ReadProcessMemory`, драйверы, обход античита.
- ❌ Захват экрана игры и его анализ (компьютерное зрение, «определение отдачи по картинке»).
- ❌ Симуляция/подмена ввода игры (`SendInput` в игру, макросы, аим-ассист, треггер-бот).
- ❌ Чтение внутриигровых данных (здоровье, патроны, разброс) — поэтому «динамический прицел» у нас только от **наших собственных** сигналов: время, скорость движения мыши, состояние кнопок мыши. Никакой связи с состоянием игры.
- ❌ Модификация файлов/конфигов игры.
- ❌ Обфускация и пакеры (триггерят AV и античиты).

Все красные линии фиксируются в [`docs/COMPATIBILITY.md`](COMPATIBILITY.md) и в пользовательском EULA/FAQ.

### 7.2 Рекомендуемый стек (вариант A)

**Ядро (Rust, всегда в памяти во время игры):**

| Задача | Крейт |
| --- | --- |
| Win32/DXGI/D2D/DComp | `windows` (официальный, фичи `Win32_Graphics_Direct2D`, `DirectComposition`, `DXGI`) |

| Конфиг/миграции | `serde` + версионирование + `semver` |

**UI настроек (отдельное окно, уничтожается при закрытии):**

Tauri 2 (`tauri`, `tauri-plugin-updater`, `tauri-plugin-single-instance`, `tauri-plugin-autostart`) + React 18 + TypeScript + Vite + Tailwind CSS + shadcn/ui (Radix) + Zustand + React Hook Form + Zod (дублирует схему DSL на фронте) + `react-i18next` + Canvas 2D для превью (тот же рендер-код, что и в оверлее, портированный на TS — либо превью запрашивает растр у ядра, чтобы WYSIWYG был честным).

> **Решение WYSIWYG:** превью в UI обязано совпадать с оверлеем пиксель-в-пиксель. Поэтому рендер DSL реализуется один раз (Rust), а UI получает готовый растр/векторный снапшот по IPC. Canvas-реплика на TS — только как fallback для мгновенной интерактивности, с периодической сверкой по «золотым» PNG.

**Инфраструктура:** GitHub Actions (windows-latest), `cargo` + `tauri build`, подпись кода, артефакты (MSI/NSIS + portable), автообновление по подписанному манифесту, Sentry/глагол-аналог для крашей (opt-in), релиз-ноты автоматически.

### 7.3 Что нужно проверить на M0 (spike) до принятия стека окончательно

1. Прозрачное DComp-окно поверх borderless-игры в CS2/Valorant: видно ли, мерцает ли, есть ли просадка FPS.
2. `UpdateLayeredWindow` vs DComp: задержка, CPU, артефакты на 240 Гц.
3. Скрытие системного курсора: `ShowCursor(false)` в чужом процессе не работает → проверить `SetSystemCursor(blank)` + надёжное восстановление после `taskkill /F`.
4. Детект FSE-режима активного окна (эвристики: размеры окна = экран, `DwmGetWindowAttribute`, `SHQueryUserNotificationState`).
5. `RegisterHotKey` во время игры с raw input — долетают ли комбинации.
6. Ресурсы: реально достижимые ОЗУ/CPU у Tauri-приложения с уничтоженным окном настроек.

Результат M0 — короткое решение «идём по варианту A / переключаемся на B» с цифрами.

```

```

```

## 9. Формат прицела и ИИ-конвейер (суть)

Полная спецификация — [`docs/CROSSHAIR_DSL.md`](CROSSHAIR_DSL.md), тексты для UI — [`docs/AI_CROSSHAIR_PROMPT.md`](AI_CROSSHAIR_PROMPT.md).

### 9.1 Почему декларативный JSON, а не «любой код»

Пользователь приносит код от сторонней модели. Если выполнять его как есть — получаем произвольное исполнение чужого кода в приложении, которое работает во время игры. Поэтому основной формат импорта — **декларативный DSL**: геометрия + стили + ограниченные выражения. Он:

- проверяется JSON-схемой и дополнительными лимитами (уже реализовано: [`schema/crosshair-v1.schema.json`](../schema/crosshair-v1.schema.json), негативные тесты в [`schema/tests/invalid/`](../schema/tests/invalid/));
- компилируется в `DrawList` один раз → статичный прицел стоит 0% CPU;
- не содержит ссылок наружу (никаких `http://`, только data-URI);
- даёт предсказуемый и понятный ИИ-контракт: «верни один JSON-объект по схеме».

Дополнительные форматы импорта: **SVG** (растеризация `resvg`, скрипты не исполняются в принципе), **PNG/WebP** (своя картинка как прицел), и — только как P2-опция с отдельным предупреждением — **JS-Canvas в песочнице** (QuickJS: без DOM, без сети, бюджет 2 мс/кадр, детерминированный RNG, API-allowlist).

### 9.2 Конвейер ИИ-импорта (7 шагов)

1. **Карточка в галерее** «Создать прицел с ИИ» → модалка инструкции.
2. Пользователь описывает желание в поле (опционально) → **сборка промпта**: системная часть (роль, контракт «только JSON»), вложенная схема DSL v1, 2 примера, чек-лист самопроверки, описание пользователя. Кнопки копирования RU/EN.
3. Пользователь вставляет промпт в **любой** ИИ-сервис (ChatGPT, Claude, Gemini, DeepSeek, GigaChat, YandexGPT, локальная модель) — приложение в сеть не ходит.
4. Полученный ответ → «Галерея → Импорт из ИИ» → вставка.
5. **Нормализация:** снять markdown-обёртки, вытащить первый валидный JSON-объект, исправить частые ошибки модели (одинарные кавычки, trailing comma, `rgba()` вместо hex, координаты в пикселях экрана вместо холста) — с явным сообщением «исправлено автоматически».
6. **Валидация:** схема → лимиты → семантика (дубли id, несуществующие `target` в bindings, выражения вне белого списка) → превью. Ошибки показываем человеком: «`layers[3].fill`: ожидался цвет вида `#RRGGBBAA`, получено `red`».
7. **Сохранение** в «Мои» с меткой `source: ai` + кнопка «Копировать запрос на исправление» (если не прошло).

### 9.3 Требования к промпту (что уже подготовлено в AI_CROSSHAIR_PROMPT.md)

- Жёсткий контракт формата ответа: один JSON-объект, без markdown, без пояснений.
- Встроенная схема (сжатая) + таблица лимитов + 2 полных примера.
- Инструкция «если не уверен — упрощай»: лучше валидный простой прицел, чем красивый невалидный.
- Чек-лист самопроверки из 8 пунктов, который модель прогоняет перед ответом.
- Отдельные мини-промпты для доработки: «сделай 5 вариантов», «перекрась в X», «добавь обводку», «сделай анимацию», «исправь ошибки».
- Версия промпта (`promptVersion`) — чтобы при изменении схемы старые импорты не ломались.

### 10.1 Карта экранов

```

      ├─ Пресеты (быстрый список)

│    ├─ Модалка «Создать с ИИ»  ← инструкция + копирование промпта
│    └─ Модалка «Импорт»        ← вставка кода, валидация, превью, ошибки
├─ 2. Редактор           (слои · холст-превью · инспектор · таймлайн анимаций · reactive-привязки)

### 10.2 Принципы

1. **Превью — главное.** Пользователь всегда видит прицел на реалистичном фоне, а не на белом холсте. Фоны: нейтральные «игровые» сцены (свои, лицензионно чистые) + возможность подставить свой скриншот.
2. **Ноль модалок там, где можно без них.** Настройки применяются мгновенно (live), отмена — `Esc`/Undo.
3. **Слайдер + число всегда вместе.** Никаких «магических» значений без возможности ввести точно.
4. **Ошибки объясняют, что делать.** Каждая ошибка импорта содержит путь к полю, ожидаемый формат и кнопку исправления.
5. **Опасное — с подтверждением.** `system-blank` для курсора, сброс настроек, удаление пресета.
6. **Тёмная тема по умолчанию**, акцент настраивается, плотность UI (comfort/compact).
7. **Скорость важнее анимаций:** UI отзывается ≤ 100 мс на любое действие, тяжёлые операции — с прогрессом.
8. **Никакого «требуется аккаунт»** и никаких сетевых зависимостей в основном сценарии.

### 10.3 OSD-уведомления поверх игры

Маленький ненавязчивый тост в углу (отдельное окно, тоже click-through, авто-скрытие 2 с): «Пресет Valorant применён», «Оверлей скрыт (Ctrl+Alt+H)», «Игра в эксклюзивном fullscreen — переключите на borderless», «Импорт не прошёл: …». Отключается полностью.

## 11. Совместимость и античиты

Кратко (полностью — [`docs/COMPATIBILITY.md`](COMPATIBILITY.md)):

- **Borderless/windowed:** работаем. На Windows 11 большинство игр и так через flip-model, поэтому оверлей виден даже когда игра называет режим «Fullscreen».
- **Эксклюзивный fullscreen (FSE):** DWM отключается → оверлей не виден. Детектим и подсказываем. План Б — виджет Xbox Game Bar (поддерживает pinning + click-through), но он тоже не работает в FSE и добавляет накладные расходы.
- **Античиты:** наша модель (внешнее окно, без инжекта/памяти/ввода) — та же, что у легально продающихся в Steam/MS Store прицел-оверлеев, которые заявляют совместимость с Vanguard/EAC/BattlEye. Но: (а) гарантий никто не даёт, античит может изменить политику; (б) сторонние платформы (FACEIT, ESL, ESEA) могут запрещать любые оверлеи своими правилами — это риск не бана античитом, а нарушения правил лиги. Пишем об этом прямо в приложении и на сайте.
- **Подпись кода обязательна.** Неподписанный оверлей = SmartScreen + подозрение AV + подозрение античита. OV/EV-сертификат закладываем в бюджет релиза.
- **Матрица тестирования** (CS2/VAC, Valorant/Vanguard, Apex/EAC, Fortnite/EAC+BattlEye, PUBG/BattlEye, R6/BattlEye, Tarkov/BSE, The Finals/EAC, Delta Force/ACE, Overwatch 2, плюс FACEIT-клиент) — обязательный чек-лист каждого релиза, результаты публикуем.

## 15. Дистрибуция и монетизация

- **Каналы:** сайт (прямая загрузка, portable + установщик), Microsoft Store (доверие + «Vanguard-safe» витрина), Steam (как у HudSight/Crosshair X — платная витрина даёт маркетинг). GitHub Releases, если делаем open source.
- **Модель (принято, Q4):** полностью бесплатно, без Pro-tier и без подписки. Опционально — донаты (GitHub Sponsors / Boosty) и ссылка в «О программе». Никаких платных фич и никаких «премиум-паков».
- **Open source (принято, Q3):** репозиторий открыт целиком — ядро, DSL, схема, валидатор, галерея пресетов. Это главный аргумент доверия: любой может прочитать код и убедиться, что красные линии из §3.3 соблюдены. Лицензии: MIT (код) + CC0 (пресеты), финализируем на M8. Следствие для процесса: код пишется сразу «как публичный» — без секретов в конфигах, с внятным CONTRIBUTING и issue-шаблонами (M8).
